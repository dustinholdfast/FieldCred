Sample audit CSV

When a GC or insurer asks who is expiring, this is the shape of the file. Example data only — not a real crew.

FieldCred’s admin dashboard exports expiring and expired certifications (not valid, not missing-date). Filename in the app: fieldcred-expiring-expired.csv. The sample below uses the same header and quoted fields the app writes.

Download example CSV

Example data. Names, issuers, and dates are fictional. They are not a customer roster. Status labels are exactly the in-app labels: Expiring and Expired (other labels in the product are Valid and No date, which this export omits).

Header

Worker,Certification,Issuer,Expires,Status

That string is hard-coded in the admin export. Each value is CSV-quoted. Expires is ISO YYYY-MM-DD. Status is the label from the status helper, not a stored field — the app derives it from the expiry date versus today (60-day renewal window by default; the dashboard can widen the window to 30/60/90/180 days before export).

How to read OSHA rows

OSHA Outreach student course completion cards have no federal expiration (Maritime printed expirations ended 1 April 2019). The date in Expires is the recency date you track for the jobsite or your own policy — not a date OSHA printed as “this card dies.” If a GC wants a 30-hour class taken in the last five years, that is a GC rule. See how to verify an OSHA 10.

What this file is for

  • Show a GC or insurer the column layout before you send a live export.
  • Map a spreadsheet onto FieldCred without inventing extra columns.
  • After a bounce, send only the workers who are actually expiring or expired — the live export’s job. Workflow: staffing gate-rejection playbook.
